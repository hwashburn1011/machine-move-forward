# Graphics-v3 walker authoring notes

## Scope

`tools/art/graphics_v3/machine.py` authors a visual-only walker shell for Machine Move Forward. The graphics-v2 review image showed the runtime machine's side as a long mostly blank wall and its prow as a single broad blade. This pass replaces those surfaces with a broad manufactured silhouette: pressed side shells, rolled shoulders, lower doublers, real service doors with gaskets, handles and recessed fasteners, sparse directional vents, perimeter weld beads, formed engine casings with bands, a recessed radiator and routed coolant pipes, and a layered fabricated prow with cheeks, ribs, gussets, and a center shoe. The prow also includes an extruded raked blade matching the runtime plough profile, a separate cutting edge, and five follow-the-rake reinforcement ribs.

The walker keeps a small four-material palette (`PaintSage`, `Graphite`, `BareSteel`, `Rubber`). Each material embeds authored 1024px base-color, normal, and ORM raster maps in the staged GLB. Curved casings use 40-sided cylinders and smooth shading; rolled edges use four-segment bevels with weighted normals. The generated LOD0 is 98,708 triangles, below the 120k allocation.

## Runtime contract

The generator uses the runtime's machine-local axes: +X port/starboard, +Y up, and +Z aft, with the prow at -Z. The deck remains 10 x 16m with center height 3.6m and walk surface 3.69m. The lower engine-room floor is Y=0.6. The visual shell leaves the stairwell at x=[-3,-1], z=[-2,2] clear, with the aft edge of the coaming open for the existing ramp. No visual crossbeam is placed through the lower room.

The GLB has modular roots `MMF_HullSkin`, `MMF_EngineSkin`, `MMF_ProwSkin`, `MMF_DeckTrim`, and four exact-handoff leg roots: `MMF_LegHousing_front-left`, `MMF_LegHousing_front-right`, `MMF_LegHousing_rear-left`, and `MMF_LegHousing_rear-right`. The housing roots are hull-side mounting collars at the existing runtime hips (x=+/-6, y=3.1, z=+/-4.5). Each leg also has five top-level local-pivot modules named `MMF_WalkerLeg_<leg-id>_<Hip|Thigh|Knee|Shin|Foot>`. The Hip and Thigh modules start at local origin; the Knee and Shin modules attach at the knee pivot, with the shin extending local -Y to 2.1m; the Foot module attaches at the foot pivot with its sole at local Y=0 and its pad rising to Y=0.3. The runtime colliders, deck cells, plough, and IK remain authoritative.

The six fixed runtime equipment envelopes have matching closed visual roots: `MMF_Equipment_generator`, `MMF_Equipment_fuel-tank`, `MMF_Equipment_workbench`, `MMF_Equipment_crate-a`, `MMF_Equipment_crate-b`, and `MMF_Equipment_collector`. They use formed casings, bands, fan/vent details, drawer faces, crate ribs and latches, and a closed winch housing with guide rollers. The export audit checks every mesh against its corresponding `MachineGeometry.equipment` center and size.

## Evidence

The CPU Blender 5.1 batch generated:

- [`machine-walker.glb`](../../../assets/graphics-v3/staging/machine-walker.glb)
- [`machine-walker.blend`](../../../assets/blender/graphics-v3/machine-walker.blend)
- [`machine-walker-manifest.json`](../../../assets/graphics-v3/staging/machine-walker-manifest.json)

The staged GLB is 14,898,348 bytes, contains 34 mesh objects, 4 materials, and 12 embedded PNG images. It contains 98,708 triangles, below the 120k allocation. The manifest records bounds, roots, triangle count, extents, stairwell, lower-room intrusion audit, fixed-equipment bounds, and leg-pivot contract. The full exported bounds are approximately x=[-6.79,6.79], y=[-2.05,6.70], z=[-10.989,7.925]; local articulated modules occupy intentional pivot-space coordinates until the runtime rehomes them under the animated leg groups.

The generator audit found zero authored static vertices inside the runtime lower-room walk volume (0.6<Y<3.51, |X|<4.4, |Z|<7.5). Engine casings and coolant pipes stay within the existing aft engine envelope. The starboard deck rail is split at z=[-1.2,1.2] for the retractable expedition gate, and the above-deck prow armor covers the existing runtime prow block. The equipment audit reports zero envelope overflows; the foot modules report local bounds Y=[0.0,0.3] for all four legs.

Khronos validation reports zero errors. It records the same `MESH_PRIMITIVE_GENERATED_TANGENT_SPACE` warning as the v2 authored pack: the GLB carries UVs, smooth normals, and packed normal maps, while tangent vectors are generated by the runtime loader. Blender's optional exported tangents were tested but produced a zero-length tangent accessor, so they are intentionally omitted for schema correctness.

The script runs with `--background --factory-startup` and only writes the v3 source/staging/docs paths. No `src/`, runtime public, graphics-v2, or live Blender/MCP state is modified.
